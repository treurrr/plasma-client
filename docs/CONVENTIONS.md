# Conventions

Several people work on this tree at once, each in a git worktree of their own.
These rules are what lets their branches merge without anyone resolving a
conflict by hand. Section 5 of `docs/PARITY-REVIEW.md` says who owns which
files; this says how to work in them.

## Where things go

The play state and the interactive client are both split by area. The areas
are the same on both sides: world, entities, player, ui (screens on the client
side), sound and data.

| | Owned by one area each | Shared, touched only at a marked hook |
|---|---|---|
| Packets | `src/session_<area>.cpp`: `Session::handle_<area>` and that area's helpers | `src/session.cpp` (connection, login, configuration, the chain in `handle_play`) |
| Session state | the area's `<Area>State` struct in `include/mcpp/session.hpp` | the public accessors in the same header |
| Session events | `SessionEvents::<Area>` in `include/mcpp/session.hpp` | `on_status`, `on_disconnect` |
| Per-frame client work | `src/client/<area>.cpp` | `src/client/play.cpp` |
| Client state | the area's `<Area>Area` struct in `src/client/game.hpp` | the core members of `Game` |
| Subcommands | - | `src/tools/client_main.cpp` |

- **Nobody edits `session.cpp`, `client_main.cpp` or `play.cpp` outside their
  marked hook.** A new packet goes in the `handle_<area>` of the area it
  belongs to; `handle_play` already asks every area in turn. New per-frame work
  goes in that area's hooks in `src/client/<area>.cpp`.
- Every area has the same six client hooks, called by `play.cpp` in a fixed
  order: `bind` (hang handlers on the session's events), `start` (once the
  first chunks are in and the window is open), `input` (on the frame's keys),
  `tick` (after the frame's packets are applied), `draw` and `stop`. They exist
  for every area already, empty where unused, so filling one in never touches
  `play.cpp`. The order is written out in `game.hpp` and in the loop itself.
- **Shared structs** (`Entity`, `ItemStack`, `Dimension`, `Biome`, and each
  area's state struct): a block that needs a new field adds it at the **end**
  of the struct, in one commit, with the block letter in the commit subject,
  and rebases onto main the same day. Two blocks appending to the same struct
  at the end merge cleanly; two blocks editing the middle do not.

## Generated tables

- **Packet ids**: `src/proto/packet_ids_gen.cpp` and
  `include/mcpp/proto/packet_ids.hpp` hold every packet of every state, both
  directions, for 774 and 776, named as the report names them without the
  `minecraft:` prefix (`debug/` becomes `debug_`). A packet a version does not
  have is -1. Nobody regenerates them to handle a packet; they are regenerated
  only to add a protocol version, and `tools/gen_packet_ids.py` writes both
  files itself, so never redirect its output.
- **Other generated tables** (`components_gen.cpp`, `metadata_gen.cpp`) are
  generated by a script in `tools/` and checked in, like the packet ids, and
  written the same way: complete or not at all.
- **Tables read from the game** (block sounds, collision shapes, entity
  sizes, entity model layers) are never committed: an exporter in `tools/`
  asks the remapped client jar, and `tools/bake_all.py` writes the table into
  the data directory as `<name>-<protocol>.txt`, beside the textures.
- **Hand tables** (`data/hardness.txt`) are text, one row per block, sorted by
  registry name, so two people editing different rows merge.

## Recordings

Recordings live in `corpus/`, which is not in the repository: they are server
output, made locally with `plasma-client record`. They are append-only, one per
block, named `<area>-<what>.plrc` (`world-nether.plrc`, `data-inventory.plrc`),
so no two people ever write the same binary file. `corpus/README` says how to
make one.

## Vanilla citations

- A function that ports a vanilla method opens with the one-line citation
  `` // `Class.method`: what it does. `` (several: `` `A.b`, `C.d` ``). It is
  the one comment the ~1% rule always allows. Our own approach cites nothing.
- A parity fix starts with `python3 tools/port_ledger.py where`, `class` or
  `todo`, never with a grep, and a branch runs
  `python3 tools/port_ledger.py check --base main` before it is merged: it
  must report no stale citation. `docs/PORT-LEDGER.md` has the details.
- Verdict rows go in `tools/port_map/<area>.tsv`, one file per area or batch,
  so two people adding rows don't edit the same file.

## Tests

Each block adds `tests/test_<area>.cpp` and one line, `mcpp_test(<area>)`, in
`CMakeLists.txt`. `tests/test_protocol.cpp` is not extended further.

## Build directories

Each worktree builds in its own `build-<name>/`; `build-*/` is ignored.
`build-dev/` belongs to the main checkout.

## Documents

Line references in `docs/PARITY.md` and elsewhere are replaced by function
names or removed; they were wrong within a day.
